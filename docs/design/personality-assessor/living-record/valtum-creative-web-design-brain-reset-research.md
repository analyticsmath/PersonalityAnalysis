# 0. Status and decision

The current Personality Assessor marketing/auth visual system is not being treated as a design that needs incremental repair.

It is being treated as evidence that the **creative model was wrong**.

The repeated failure pattern was:

> product idea  
> → content section  
> → grid  
> → image placement  
> → absolute positioning  
> → GSAP/Lenis/SVG/Three  
> → describe the result as spatial/cinematic

That process can create technically sophisticated pages while preserving ordinary marketing-site composition.

This dossier replaces that process.

No coding-agent implementation brief should be created from the existing section architecture.

The new sequence is:

> **PRODUCT TRUTH  
> → WORLD  
> → PROTAGONIST  
> → DOMINANT MATERIAL  
> → STATIC COMPOSITION FRAMES  
> → CONTINUITY  
> → INTERACTION PHYSICS  
> → ROUTE OPERATING MODES  
> → MOBILE/FALLBACK WORLD  
> → TECHNOLOGY  
> → IMPLEMENTATION**

The most important correction is that **technology moves to the end**.

# 2. The central diagnosis: why the previous design brain failed

The failure was not primarily missing motion.

The failure was not primarily insufficient photography.

The failure was not primarily lack of advanced libraries.

The failure was that the design process started from **webpage architecture** instead of **world architecture**.

## 2.1 Section-thinking was mistaken for composition

The previous mental template was still recognizable as:

- hero;
- explanation;
- selection;
- transformation;
- three states;
- proof;
- CTA;
- footer.

Even after cards were removed, the semantic arrangement remained:

- heading block;
- supporting paragraph;
- rectangular media;
- labelled interaction;
- equal information groups.

Absolute positioning did not fix this.

Transparent backgrounds did not fix this.

SVG paths did not fix this.

Three.js did not fix this.

A weak composition does not become an authored composition when animated.

## 2.2 “Spatial” was defined geometrically, not perceptually

Putting elements at different x/y coordinates is not spatial art direction.

Spatial authorship requires:

- foreground and background ownership;
- occlusion;
- unequal scale;
- focus;
- depth;
- a dominant mass;
- a clear eye path;
- continuity between states;
- visual tension;
- meaningful negative space.

A set of labels distributed around a viewport is still a diagram if the eye does not experience a world.

## 2.3 The product thesis became explanatory graphics

“Evidence changes meaning in context” repeatedly became:

- paths;
- labelled zones;
- provenance nodes;
- temporal blocks;
- framework quadrants.

Those can be useful supporting representations.

They are not a complete visual identity.

The strongest references do not merely diagram their subject.

They **behave like their subject**.

## 2.4 Media became inventory instead of editing

Adding more images solved scarcity but not design.

High-end media direction means deciding:

- when an image owns 90% of the viewport;
- when only a fragment is visible;
- when the same image returns under a different crop;
- when media becomes foreground;
- when it becomes a transition;
- when typography is occluded by it;
- when the user enters the image;
- when media disappears to create a quiet field.

The previous design mostly asked:

> Which image goes in this section?

The new design process must ask:

> What is the cinematic role of this image in the sequence?

## 2.5 Motion libraries were treated as effects inventory

A library name is not an art direction.

Lenis does not mean “smooth scrolling exists.”

Three.js does not mean “add depth.”

GSAP does not mean “pin this.”

Rive/Lottie does not mean “add a vector animation.”

The correct question is:

> What should the user perceive changing, and why does that change belong to the product?

Only then choose a technology.

# 3. WHITE DESERT — PRIMARY ART-DIRECTION BLUEPRINT

**Current site:** https://white-desert.com/  
**Existing Valtum corpus coverage:** full desktop homepage + South Pole & Penguins itinerary  
**Current project credit:** White Desert footer credits Malvah; Malvah's current public announcement describes the project as translating the wonder, scale, emotion and operational detail of Antarctica into an immersive digital home.

White Desert is the most important reference in this reset because it demonstrates the difference between:

> a website about a subject

and

> a website whose entire visual system is governed by the subject.

---

# 4. White Desert: one-sentence design thesis

The site behaves like a **controlled expedition from awe to trust**.

It does not begin by explaining White Desert as a company.

It first makes Antarctica emotionally dominant.

Then it gradually introduces:

- trip choice;
- human authority;
- camp detail;
- coordinates;
- transport;
- time;
- distance;
- temperature;
- planning;
- operational process.

The commercial logic arrives **inside the world**, not before it.

This is the core pattern:

> **emotion → orientation → specificity → logistics → confidence → action**

That is radically different from:

> H1 → product value proposition → features → how it works → CTA.

---

# 5. White Desert: the protagonist is a world, not a UI object

White Desert does not need a small persistent 3D icon because Antarctica itself is persistent.

The protagonist has multiple interchangeable representations:

- landscape;
- weather;
- mist;
- whiteout;
- geographic coordinates;
- distance;
- camps;
- aircraft route;
- temperature;
- scientific/extreme-environment language;
- human stories.

This matters.

The protagonist is not literally the same DOM element.

It is a **consistent subject-state**.

That means persistent-protagonist design does not require one mascot floating through every route.

It requires the user's brain to feel:

> “I am still inside the same world.”

### Transferable lesson

For Personality Assessor, the protagonist cannot merely be “a sentence that is still somewhere on screen.”

The product needs an identifiable visual/semantic constant that can survive:

- context;
- interpretation;
- career environment;
- provenance;
- time.

The exact embodiment must be solved in the next creative-thesis phase.

Do not assume the old “Evidence Field” execution is correct.

# 6. White Desert: first 10 seconds

The existing live report recorded:

- cinematic Antarctic media immediately visible;
- transparent navigation;
- a very large condensed `ANTARCTICA` title;
- minimal supporting premise;
- `Watch Film`;
- no long blocking loader;
- interaction available while media continued loading.

This is a crucial standard.

The first viewport establishes:

1. **where you are**;
2. **how large the world is**;
3. **what emotional register the brand owns**.

It does not try to explain the whole business.

### The high-value lesson

A first viewport should be **world entry**, not content summary.

The visitor should not need to read three paragraphs to know whether the site has a point of view.

### Personality Assessor implication

The redesign must answer, visually, in the first three seconds:

> What world am I entering?

Not:

> What are the four frameworks?

Not:

> What is the methodology?

Not:

> What are the feature benefits?

The current design failed because the first viewport could still be parsed as web content blocks.

# 7. White Desert: media is the structural mass

White Desert's visual authority comes from photography/film taking over the page.

Media is not a rectangle assigned to a column.

The landscape determines:

- where type can sit;
- how much negative space exists;
- when the interface becomes quiet;
- how the next state can emerge;
- how scale is perceived.

The visual hierarchy often becomes:

> environment first  
> typography second  
> controls third.

This hierarchy is exactly why the site feels cinematic rather than “designed marketing.”

### Important distinction

Full-bleed alone is not enough.

A generic stock photo with text on top is still generic.

White Desert succeeds because:

- the media is subject-specific;
- crop and scale express physical vastness;
- motion language uses atmospheric qualities;
- operational information later validates the spectacle.

# 8. White Desert: atmosphere becomes transition grammar

The existing corpus identified White Desert's recurring motion language as:

- mist;
- blur;
- opacity;
- scale;
- layered media;
- moderate Lenis-like smoothing.

The current homepage explicitly exposes a `Mist transition` asset around the Cape Town → Wolf's Fang chapter.

This is one of the strongest lessons in the entire corpus.

The transition is not:

> “we have GSAP, so fade up the next section.”

The transition comes from the physical world:

> visibility changes in Antarctica.

### Design reasoning

A transition feels authored when it has a **subject-derived cause**.

White Desert can plausibly:

- obscure;
- reveal;
- recede;
- expose;
- dissolve distance;
- move through whiteout.

Those are Antarctic verbs.

### Personality Assessor translation

We need equivalent verbs that are genuinely native to professional evidence.

Candidates will be tested later, but the method is clear:

Do not ask:

> Which transition looks premium?

Ask:

> What happens to evidence when context changes?

That answer should generate the transition.

# 9. White Desert: the intensity curve is designed

The corpus's most useful observation is that White Desert changes density deliberately.

Its broad homepage rhythm is approximately:

### State A — spectacle
Full environmental media.

### State B — quiet editorial
“The Last Continent” language and breathing room.

### State C — choice
Trips and destinations.

### State D — human authority
Founder testimony.

### State E — environment/detail
Camp imagery, camp identity, coordinates.

### State F — poetic pause
Quote.

### State G — operational cinema
Cape Town → Wolf's Fang route, map/geography, flight data, temperature.

### State H — practical confidence
Consultation, planning, safety, departure.

### State I — identity/utility ending
Film, rates, enquiry, quote, footer.

This is much stronger than constant stimulation.

### Why

If every viewport is kinetic, nothing feels important.

Quiet scenes create contrast.

The viewer can recover.

The next high-complexity state has somewhere to rise from.

### New doctrine

Every future Valtum storyboard needs an **intensity graph** before implementation.

Not every scene gets a signature mechanic.

The page needs:

- peaks;
- troughs;
- anticipation;
- release;
- climax;
- conclusion.

# 10. White Desert: real logistics become visual language

This is perhaps the single most transferable decision.

The current homepage contains real data such as:

- exact camp coordinates;
- Cape Town coordinates;
- Wolf's Fang coordinates;
- 05:30 flight duration;
- 4,220 km / 2,610 mi distance;
- -5°C / 23°F average summer temperature.

The values are not generic KPIs like:

> 98% satisfaction  
> 12k users  
> 4.9 rating.

They are **world coordinates**.

They tell you where you are and what the journey means.

### Why this is sophisticated

Information, credibility and atmosphere become the same material.

The brand does not need a separate “trust section” to say it is operationally serious.

The operational truth is already visible.

### Personality Assessor translation

Use actual product truth as compositional material.

Potential categories, to be researched from the real app/backend before final design:

- evidence type;
- time of observation;
- user-supplied vs calculated provenance;
- assessment framework;
- context;
- role/environment;
- comparison basis;
- confidence/limitations where genuinely supported;
- revision history.

The key is:

> product data must orient the viewer, not decorate the page.

No KPI strip.

# 11. White Desert: geography is navigation

The Cape Town → Wolf's Fang chapter does more than display numbers.

It creates **spatial orientation**.

The user's mental model changes from:

> “beautiful Antarctica”

to:

> “I understand the actual movement into Antarctica.”

That shift from emotion to map/route is excellent storytelling.

### Transferable mechanism

A product can change representation while remaining the same world.

White Desert changes:

> footage → editorial → coordinates → route → operational process.

This is more useful than copying any one animation.

# 12. White Desert: commercial actions never disappear

Current top-level access includes:

- Experience
- Operation
- About

- Enquire.

This matters for Valtum.

# 13. White Desert: typography supports scale

The corpus found White Desert effective because typography uses:

- condensation;
- family contrast;
- scale;
- restrained interface copy.

It does not depend on 900-weight typography for every scene.

The huge title works because it belongs to environmental scale.

This is an important correction to our previous thinking.

A large title is not bad.

A large title becomes bad when:

- it is the only source of drama;
- every route repeats it;
- it is disconnected from the subject;
- it creates empty pages around itself.

### Rule

Typography size must answer:

> What physical/emotional scale is this scene expressing?

not:

> How do we make this look Awwwards?

---

# 14. White Desert: route-specific operating modes

The homepage and itinerary route do not need identical behavior.

The corpus observed:

### Homepage
Atmospheric and broad.

### Itinerary
Full-bleed destination hero, anchor navigation, historical/scientific detail, galleries and day-by-day logistics.

The brand remains coherent because the protagonist is stable.

### High-value lesson

Route identity comes from **content function**.

Not every route needs the homepage's strongest trick.

For Personality Assessor:

- Career should not be Home with different copy.
- Progress should not be Home with a time image.
- Trust should not be Home with technical labels.
- Methodology should not be forced cinematic if reading is the correct mode.

Shared world, different operating modes.

---

# 15. White Desert: resilience and performance

The corpus identified White Desert's media/HTML experience as remaining usable while advanced layers were available.

The current homepage exposes information and actions without requiring the visitor to wait through a theatrical blocking loader.

That is premium behavior.

### But White Desert is not perfect

The existing report also observed roughly 5-second internal itinerary transitions.

That may preserve continuity, but for Valtum it is too expensive unless absolutely necessary.

The corpus's warning remains:

> around 1–1.5 seconds is the point where a transition increasingly risks feeling like waiting.

### Transfer

Borrow:
- continuity;
- destination atmosphere;
- route handoff.

Do not borrow:
- delay.

---

# 16. White Desert: what NOT to copy

White Desert itself contains patterns that conflict with Valtum.

Do not copy:

- the numbered six-step “How it works” architecture;
- a conventional utility-heavy footer as a template;
- giant brand-wordmark ending by default;
- long route-transition delays;
- Antarctic visual motifs;
- mist simply because mist looks cinematic;
- luxury-travel copy cadence;
- its exact condensed-type treatment.

The correct transfer is:

> **subject becomes environment, environment becomes motion, operations become information design.**

# 18. LENIS.DEV — SECOND PRIMARY BLUEPRINT

**Current site:** https://lenis.dev/  
**Product:** open-source smooth-scroll library by darkroom.engineering

Lenis is important for two different reasons:

1. the technology is foundational for the future Valtum motion substrate;
2. the website demonstrates an extremely important design principle:

> **the page itself demonstrates the product.**

---

# 19. Lenis: the product and the interaction are the same thing

The homepage begins with:

> Smooth Scroll  
> scroll to explore

That is not clever copy sitting beside a demo.

The act the user performs to explore the site is the thing being sold.

This creates immediate causal coherence.

### Compare with our previous Personality Assessor

We told visitors:

> evidence changes in context.

But the experience mostly asked them to:

> scroll through sections that explain evidence changing in context.

That is not enough.

### New requirement

The redesigned Personality Assessor must let the visitor **experience the core product proposition through the page's behavior**.

If context changes evidence, the page should make that change perceptually undeniable.

If provenance matters, the user should be able to inspect it.

If time matters, returning/revisiting should visibly alter the record.

The marketing site should behave like a conceptual demo of the product's logic.

---

# 20. Lenis: smoothness is not the main point

Lenis explicitly says it began as an internal tool for keeping WebGL and DOM synchronized.

Its current page says:

- immersive interfaces;
- one feel across wheel/trackpad/touch;
- WebGL and DOM moving together frame-for-frame;
- native scroll;
- no hijacked scrollbar;
- accessibility retained.

This rewires how Lenis should be used in our design system.

### Old interpretation
Lenis = nice easing.

### Correct interpretation
Lenis = **one temporal authority** for the visual world.

That temporal state can drive:

- camera;
- media;
- typography;
- masks;
- SVG;
- route-local data;
- velocity response;
- active context;
- settling.

### Architecture doctrine

```text
USER INPUT
   ↓
LENIS
   ↓
TEMPORAL STATE
(position / progress / direction / velocity / settling)
   ↓
GSAP / ScrollTrigger / Three / SVG / media / typography
```

Do not have independent systems inventing their own scroll clocks.

---

# 21. Lenis: the website has a single conceptual sentence

The current Lenis content repeatedly returns to one claim:

> web scrolling can feel materially better without sacrificing native behavior.

Sections such as:

- Why smooth scroll?
- Lenis runs the web
- so we built web scrolling
- Enter Lenis
- As it should be
- feature capabilities
- open source

all reinforce that one thesis.

The page is not trying to tell five unrelated product stories.

### Transfer

A flagship landing experience needs a **single strong sentence** that every state re-proves.

The previous Personality Assessor homepage attempted to explain too much.

---

# 22. Lenis: proof becomes content

The “Lenis runs the web” section does not merely say:

> trusted by leading brands.

It surfaces actual sites using Lenis, including Lando Norris.

That is a strong form of proof-of-life.

### Principle

Use real working systems as evidence.

For Valtum and the product sites, real application behavior should replace generic credibility strips.

---

# 23. Lenis: features are secondary to felt experience

The site eventually lists capabilities:

- one-line setup;
- Framer plugin;
- snap;
- attached element;
- horizontal and vertical;
- infinite scrolling;
- lightweight under 4kb.

But the visitor has already **felt** the core value before reading the list.

This is the correct ordering:

> experience → explanation → specification.

Our previous website repeatedly used:

> explanation → example → animation.

Reverse that.

---

# 24. Lenis: technology constraints matter to art direction

The official Lenis documentation/GitHub notes practical constraints:

- different frame rates in Safari depending on display/low-power mode;
- limitations around iframes;
- older iOS sync behavior;
- nested-scroll complexity.

This reinforces a permanent rule:

> motion art direction must be designed with degraded states from the start.

Not after launch.

---

# 25. Lenis: design lesson for fast scroll

The 57-page corpus already concluded:

> smoothing matters only when user intent survives.

This is fundamental.

A cinematic sequence that requires a user to scroll exactly as slowly as the designer's screen recording is bad interaction design.

For every future pinned/long scene we need two narratives:

### Slow intent
Full intermediate choreography.

### Fast intent
Skip gracefully to the next complete meaningful state.

Reverse must also reconstruct cleanly.

# 28. Lottie: the important idea is causality, not animation playback

The most useful lesson for Personality Assessor is the difference between:

### Timeline animation
“At 40% scroll, play this sequence.”

and:

### State-machine motion
“When the product state changes, the visual state changes because of that event.”

That is closer to product behavior.

Possible future uses include:

- a small persistent evidence/provenance object;
- inspectable state change;
- context switching;
- response to a real product flag.

But Lottie/Rive should not become page decoration.

- interactive state thinking;
- live product demonstration;
- lightweight vector runtime;
- motion tied to data.

- SaaS information architecture.

# 65. WHAT ACTUALLY MAKES THESE SITES FEEL TOP TIER

The answer is not “they animate a lot.”

## 65.1 They choose one thing to believe in

White Desert believes in Antarctica.

Lando believes in the athlete/racing world.

Oryzo believes in the coaster joke so completely that it can build an entire technical mythology around it.

The Watch believes in the object.

A weak site has many ideas.

A strong site has one idea with many consequences.

---

# 66. They design a world before designing components

The page does not look like:

> hero component  
> cards component  
> gallery component.

Components exist technically, but they are not the visual grammar.

The world owns the composition.

---

# 67. They spend complexity selectively

The best references do not make every section equally complex.

Complexity is concentrated:

- White Desert: atmosphere/geography;
- Lando: motion/data/media;
- Oryzo: persistent product transformations;
- Watch: realtime object;
- Palomino: photography;
- Moto: restrained outcomes.

### New rule

Before implementation, identify:

> the one or two places where complexity is worth spending.

Everything else supports them.

---

# 68. They use real information as visual material

This is one of the strongest shared traits.

Examples:

- race schedule;
- route coordinates;
- flight distance;
- temperature;
- camp locations;
- object specifications;
- currencies;
- product documentation.

This makes the site difficult to clone for another brand.

### Anti-template test

If the scene still works after replacing all product nouns with another software company's nouns, it is probably too generic.

---

# 69. They create continuity before motion

Continuity is not an animation library feature.

It comes from:

- protagonist;
- media;
- data;
- environment;
- object;
- repeated visual state.

Motion then makes that continuity perceptible.

---

# 70. Their intermediate frames are designed

A high-end scroll sequence is not:

> start state + end state + tween.

At 25%, 50%, 75%, the composition still needs:

- a focal point;
- hierarchy;
- legibility;
- tension.

This is where many coding-first motion systems fail.

---

# 71. They treat crop as motion

Image crop can change meaning without moving an image across the screen.

Useful operations:

- crop tighten;
- subject reveal;
- inner-image parallax;
- image expansion;
- same-source recrop;
- occlusion;
- foreground takeover.

This is often more elegant than moving five boxes.

---

# 72. They use quietness as an active state

Quiet does not mean empty padding.

A quiet state can contain:

- one sentence;
- one object;
- one piece of data;
- one small image;
- one action.

Its role is rhythm.

---

# 73. They let product semantics determine navigation

Lando's route taxonomy belongs to the athlete's world.

White Desert's navigation belongs to experience/operations.

Siena turns archive taxonomy into interaction.

The redesigned Personality Assessor navigation should eventually reflect its product model where useful, while retaining direct semantic routes.

---

# 74. They do not confuse novelty with custom cursor theatre

A global giant cursor does not make a site premium.

Contextual pointer states can be useful when they communicate a verb:

- inspect;
- drag;
- enter;
- compare.

Otherwise native pointer is often more confident.

---

# 75. They keep commercial action accessible

Creative work does not require burying:

- Enquire;
- Apply;
- Store;
- Work with us;
- documentation.

The experiment serves the product/business.

---

# 76. They end the story before the footer

The best finale answers:

> What changed emotionally or conceptually since the opening?

Then utility appears.

A giant brand name is not automatically a finale.

# 77. THE NEW DESIGNER BRAIN

This is the main output of the research.

Before designing any route, the following sequence is mandatory.

---

# 78. STEP 1 — PRODUCT TRUTH

Write one sentence that is literally true.

Not marketing.

Not aesthetic language.

For Personality Assessor, the current product truth must be re-audited from the actual application before final art direction.

The old evidence/context thesis may survive, but it is no longer protected simply because we used it before.

---

# 79. STEP 2 — WORLD

Answer:

- Where does the visitor feel they are?
- What physical/material qualities define this world?
- Is it documentary, spatial, analytical, temporal, archival, environmental?
- What is the emotional temperature?
- What is the scale?
- What is near?
- What is far?
- What can obscure something else?
- What can transform?

If these cannot be answered, do not design a hero.

---

# 80. STEP 3 — PROTAGONIST

The protagonist must pass five tests.

### Recognizable
The eye can point to it.

### Persistent
It can survive multiple scenes.

### Transformable
It can change representation without becoming unrelated decoration.

### Product-specific
It could not belong to a random SaaS product.

### Finale-capable
It can carry the ending.

If the protagonist is too abstract to pass these tests, redesign it before coding.

---

# 81. STEP 4 — DOMINANT MATERIAL

Choose what visually carries most of the identity:

- documentary photography;
- one product object;
- data;
- typography;
- 3D geometry;
- video;
- environmental media;
- mixed but with one clear hierarchy.

Do not let every medium compete equally.

For White Desert, environment wins.

For Oryzo, object wins.

For Lando, person/media/data form one hierarchy.

---

# 82. STEP 5 — STATIC FRAME DESIGN

This is the stage we skipped.

For every flagship scene, design static states at:

- 0%;
- 25%;
- 50%;
- 75%;
- 100%.

For each frame define:

- dominant mass;
- focal point;
- negative space;
- image crop;
- type placement;
- depth;
- overlap;
- stable reference;
- protagonist state;
- what persists from previous frame.

### Hard gate

If the frames are not visually strong with animation paused, the motion concept is rejected.

---

# 83. STEP 6 — CONTINUITY

Every scene handoff must answer:

> What crosses the boundary?

Possible answers:

- protagonist;
- media crop;
- data value;
- line/path;
- camera position;
- mask;
- typography fragment;
- sound where appropriate;
- context state.

“Everything fades out and the next section fades in” is not continuity.

---

# 84. STEP 7 — INTERACTION PHYSICS

Only now choose verbs.

Possible categories:

- reveal;
- expose;
- separate;
- compress;
- layer;
- compare;
- rotate;
- inspect;
- drift;
- accelerate;
- occlude;
- revisit;
- trace;
- recompose.

The verb must be product-derived.

---

# 85. STEP 8 — ROUTE OPERATING MODE

Each route gets a role.

Not a layout template.

Questions:

- Is this route cinematic?
- exploratory?
- archival?
- technical?
- documentary?
- reading-focused?
- temporal?
- form/action-focused?

The operating mode determines:

- density;
- media;
- interaction;
- scroll model;
- typography;
- navigation;
- fallback.

---

# 86. STEP 9 — MOBILE AND FALLBACK WORLD

Design these **before implementation**, not after desktop.

For every flagship desktop mechanic define:

### Mobile replacement
What touch-native composition carries the same idea?

### Reduced motion
What remains meaningful without long interpolations?

### No WebGL
What owns the world?

### Fast scroll
What complete state does the system settle into?

### Resize
How is state preserved or recomputed?

---

# 87. STEP 10 — TECHNOLOGY

Only now assign technology.

## Lenis
Temporal authority and input normalization.

## GSAP / ScrollTrigger
Long-form scene orchestration.

## Motion
React presence/layout/gesture states.

## Three/R3F/WebGL
Only for spatial/camera/object behavior that cannot be expressed convincingly with DOM/media.

## Rive / Lottie
Stateful vector systems, not decorative motion stickers.

## Anime.js
SVG/path/morph specialist use.

## CSS
Simple visual states and layout.

No technology receives a scene merely because it is installed.

# 93. REJECTED DESIGN HABITS

The following mental habits are retired.

## “Make it spatial”
without specifying perceptual depth and hierarchy.

## “Add parallax”
without defining planes, ratio, ownership and meaning.

## “Use Three.js”
without an object/camera/world problem that needs realtime rendering.

## “Use a large image”
without specifying crop, visual mass and relationship to type.

## “Make the hero cinematic”
without designing the actual static frame.

## “Use a path”
when the product does not naturally require travel/trace.

## “Add more motion”
when the existing motion has no focal hierarchy.

## “Use cards but remove borders”
still card thinking.

## “Make it mobile responsive”
instead of creating another composition.

## “Implement then visually fix”
as the main creative method.
